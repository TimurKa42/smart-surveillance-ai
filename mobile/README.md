# Smart Surveillance AI — мобільна версія (Kivy)

Це окремий застосунок від десктопної версії (`../main.py` на
CustomTkinter). CustomTkinter/Tkinter не працює на Android і не
збирається в APK взагалі — тому весь інтерфейс тут переписаний на
Kivy, а от логіка нарізки відео (`video_tools.py`) і звернення до
Gemini (`gemini_tools.py`) взята майже без змін.

## Що робить застосунок

1. **Екран Setup** — при першому запуску просить встав API-ключ Gemini.
   Знизу — посилання "Немає ключа? Дізнатись, як отримати", яке
   відкриває https://aistudio.google.com/apikey в браузері. Ключ
   зберігається у `.env` в теці даних застосунку (не поруч з кодом,
   бо APK — це архів лише для читання) і більше не питається при
   наступних запусках.
2. **Екран Main** — вибір відео (нативний файловий провідник через
   `plyer`), текстовий запит, вибір моделі (3.1 Flash-Lite / 3.5 Flash),
   кнопка аналізу, звіт зі скріншотами.

## ВАЖЛИВО: APK не можна зібрати "просто скриптом"

Компіляція APK вимагає завантаження Android SDK/NDK (кілька гігабайт)
і працює лише через **buildozer на Linux** (macOS частково, Windows —
тільки через WSL). Я не можу зібрати APK за тебе прямо в цьому чаті —
у мене немає доступу до Android SDK і потрібних серверів завантаження.
Але весь код і конфігурація (`buildozer.spec`) вже готові — тобі
залишається запустити збірку на своїй машині.

## Як зібрати APK самому

### 1. Підготовка (один раз)

На Ubuntu/WSL:
```bash
sudo apt update
sudo apt install -y python3-pip build-essential git python3-dev \
    ffmpeg libsdl2-dev libsdl2-image-dev libsdl2-mixer-dev libsdl2-ttf-dev \
    libportmidi-dev libswscale-dev libavformat-dev libavcodec-dev zlib1g-dev

pip install --user buildozer cython
```

### 2. Тест на комп'ютері (без Android, швидка перевірка інтерфейсу)

```bash
cd mobile
pip install kivy plyer google-genai python-dotenv pydantic opencv-python pillow
python main.py
```

Так можна одразу побачити екран вводу ключа і основний екран, не
чекаючи довгої збірки APK.

### 3. Збірка APK

```bash
cd mobile
buildozer android debug
```

Перша збірка займе **30-60+ хвилин** (buildozer сам завантажує Android
SDK/NDK і компілює всі залежності, включно з opencv — саме він
найдовше збирається). Готовий файл з'явиться в `mobile/bin/*.apk`.

### 4. Встановлення на телефон для тесту

```bash
buildozer android deploy run logcat
```
(телефон має бути підключений по USB з увімкненою "Налагодження USB").

## macOS: як запустити і зібрати APK

**Важливо:** buildozer офіційно підтримує збірку Android **лише на Linux**.
На macOS toolchain python-for-android часто ламається (нечутлива до
регістру файлова система, відсутні потрібні бібліотеки NDK тощо). Тому
для Мака нижче два кроки: 1) звичайний локальний запуск і тест
інтерфейсу прямо на маці (без Android), і 2) сама збірка APK - через
Linux-середовище, яке не потребує встановлювати Ubuntu вручну.

### 1. Локальний запуск на Мак (перевірити інтерфейс, без Android)

```bash
cd mobile
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install kivy plyer google-genai python-dotenv pydantic opencv-python pillow

python main.py
```

Відкриється звичайне вікно застосунку (Kivy на macOS працює як
десктопна програма) - можна одразу перевірити екран вводу ключа,
вибір відео через системний діалог і сам аналіз, ще до того, як
збирати APK. Якщо вікно не відкривається з помилкою по SDL2 -
`brew install pkg-config sdl2 sdl2_image sdl2_ttf sdl2_mixer` і
спробуй ще раз (зазвичай не потрібно - pip-колесо Kivy вже містить
ці бібліотеки в собі).

### 2. Збірка APK - варіант A: GitHub Actions (найпростіше, "вишенька")

У проєкті вже лежить готовий workflow `.github/workflows/build-apk.yml`.
Він збирає APK на безкоштовній Linux-машині GitHub - тобі взагалі не
треба нічого компілювати на своєму Маці.

1. Заливаєш проєкт (весь, включно з `mobile/` і `.github/`) у свій
   репозиторій на GitHub.
2. На сторінці репозиторію -> вкладка **Actions** -> зліва обираєш
   **"Build Android APK"** -> праворуч кнопка **"Run workflow"**.
3. Чекаєш 20-40 хвилин (перша збірка найдовша).
4. Коли жовтий гурток стане зеленим - заходиш у завершений запуск,
   внизу розділ **Artifacts** -> завантажуєш `smart-surveillance-apk`
   (це zip з готовим `.apk` всередині).

Workflow запускається і автоматично при кожному push у папку `mobile/`,
і вручну кнопкою - зручно для повторних збірок, коли щось змінюєш.

### 2. Збірка APK - варіант B: buildozer у Docker (без GitHub)

Якщо не хочеш заводити GitHub-репозиторій - можна зібрати локально
через офіційний Docker-образ buildozer (Docker Desktop для Mac ставиться
з сайту docker.com, підтримує і Apple Silicon, і Intel):

```bash
cd mobile
docker run --rm -v "$(pwd)":/home/user/hostcwd kivyorg/buildozer android debug
```

Перший запуск довгий (Docker качає образ + все компілюється всередині
контейнера), готовий `.apk` з'явиться у `mobile/bin/` — прямо на
твоєму Маці, як і при звичайній збірці.

## Що варто знати перед захистом проєкту


- **opencv на Android** — важка залежність, перша збірка довга і може
  вимагати донастройки версій (`android.ndk`, `android.api` в
  `buildozer.spec`) залежно від версії buildozer. Якщо збірка падає на
  кроці opencv — це найчастіша причина проблем з мобільними Kivy+CV
  проєктами взагалі, не специфічна для цього коду.
- Мова інтерфейсу поки завжди українська при старті (без збереження
  вибору між запусками, на відміну від десктопної версії) — можна
  додати перемикач і збереження в `config.py` за тим самим принципом,
  що й API-ключ.
- Теми оформлення (світла/темна) в мобільній версії немає — зроблено
  одну сучасну темну тему за замовчуванням, це свідоме спрощення для
  мобільного UI.
